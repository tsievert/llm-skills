# Drafting a reviewer response

No R package addresses this — it is a drafting and structuring task. Treat it like
`manuscript-writing-quarto`'s stance on prose: draft and suggest, never finalize a substantive scientific
argument on the user's behalf.

## Structure

1. A short thank-you/summary paragraph (genuine, brief — not boilerplate padding).
2. One numbered point per reviewer comment, in the reviewer's original order, each followed immediately by
   the response. Quote or paraphrase the comment first so the editor can follow without the original letter.
3. For each point, state plainly: agree and what changed (with a pointer to the specific section/line/figure),
   partially agree and what changed, or disagree and why — with evidence, not assertion. A response that
   disputes a point needs to show the data or reasoning, not just restate the original claim more firmly.
4. If new analysis was run in response to a comment, report it the same way any result is reported here:
   estimate, uncertainty, method, and why that method — do not understate a new analysis that complicates the
   original story.
5. Close by noting any comment that was not addressed and why (scope, data availability, a separate planned
   study) rather than ignoring it silently.

## What this skill does and does not do

- Does: help organize the reviewer's points, draft response language the user edits, and make sure any
  numbers cited in a response (effect sizes, corrected p-values, power) are produced the way the rest of this
  skill produces them — not invented to sound persuasive.
- Does not: decide the scientific argument, concede or dispute a point on the user's behalf, or generate a
  response the user has not reviewed line by line. The user's scientific judgment is the content; this skill
  only helps structure and phrase it.
