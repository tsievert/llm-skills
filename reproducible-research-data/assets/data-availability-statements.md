# Data availability statement drafts

Drafts for the user to adapt. Fill `[...]` only with facts the user gave; never invent a DOI, repository or licence. Insert the DOI only after the
repository has issued it (a reserved DOI is not yet citable). Check the journal's own required wording and placement first
(`../references/journal-policies.md`).

## Data and code in a repository (most journals)

> The data and code supporting this study are available in [repository name] at [https://doi.org/DOI] ([licence]). Code is archived at [https://doi.org/DOI of code archive].

## Data and code in one deposit

> All data and analysis code are available in [repository name] ([https://doi.org/DOI], [licence]). The deposit includes a README, the raw and processed data, the code, and a lockfile of the software environment.

## Anonymised during review (Behavioral Ecology style)

> The data and code are available at [reviewer link] during review and will be released under a permanent DOI on acceptance.

## Data cannot be shared in full

> The [data type] are not publicly available because [specific reason, for example locations of a protected species]. [A reduced dataset with [what was changed]] is available at [DOI]. The full data can be requested from [contact] for [stated purposes].

## Third-party data

> This study uses [dataset] from [source] ([citation, DOI or URL]), available under [licence/access route]. Our derived data and code are at [DOI].

## Elsevier-style data statement (Computers and Electronics in Agriculture)

> Data availability: [Data have been deposited in [repository] at [DOI] / The data that support this study are available from [contact] because [reason]].
